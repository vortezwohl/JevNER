# JevNER 性能实验报告

日期：2026-11-03
环境：Windows 11 / Python 3.11.15 / uv 管理依赖 / jev-latest（TypeSafe API）
实验脚本：`tests/bench_performance.py`（`PYTHONPATH=. uv run python tests/bench_performance.py`）

## 1. 目的与范围

验证三项性能优化的实际收益，并测量各规模负载下的延迟与吞吐特征：

- **三级进程内缓存**：检测（窗口哈希 → 命中词元）、分型（窗口哈希 + span + 阈值 → 类型元组）、性别（人名 → 性别判定）；
- **窗口级并行**：多窗口文本在 `vortezwohl.ThreadPool` 上并发执行检测 + 分型；
- **批次级并行**：单窗口内分型批次并发提交。

范围：端到端延迟、缓存命中收益、并行加速比。不含：计费成本核算（见第 6 节估算）、API 服务端排队细粒度分析。

## 2. 系统配置

| 项 | 值 | 说明 |
| --- | --- | --- |
| 默认窗口 | 24 576 token | jev per-question 上限 32 768 减 8 192 问题余量 |
| 滑动步长 | 窗口的 50% | 相邻窗口重叠保证跨边界实体完整 |
| 检测问题批 | 256 问/请求 | Noul 检测，灰色区（0.3–0.5）二次复检 |
| 分型问题批 | 64 问/请求 | Choice 分型，小批次避免批内干扰 |
| 默认并行度 | 8 线程 | 窗口级 + 批次级并发 |

## 3. 实验结果

### E1 单文本端到端延迟（串行）

| 文本规模 | token 数 | 窗口数 | 端到端延迟 | 实体数 |
| --- | --- | --- | --- | --- |
| 短（16 字） | 16 | 1 | 8.82 s | 2 |
| 中（10 句） | 200 | 1 | 11.70 s | 11 |
| 长（120 句） | 3 490 | 1 | 36.94 s | 5 |

观察：单窗口内延迟随 token 数（检测问题数）近线性增长；长文本单窗口 3490 token 时全部检测问题已在一批内完成（3490/256 ≈ 14 批），主要时间是 14 个检测串行批次 + 分型批次。

### E2 缓存收益（同一文本二次调用）

| 调用 | 延迟 | 说明 |
| --- | --- | --- |
| 冷调用 | 14.56 s | 首次，检测 + 分型 + 性别全部真实请求 |
| 热调用 | 0.001 s | 三级缓存全部命中，零 API 请求 |
| **加速** | **≈ 11 000×** | 命中路径仅本地查表 |

### E3 窗口级并行加速比（120 句长文本，window=2048，约 4 窗口 × 检测+分型）

| 并行度 | 端到端延迟 | 相对 1 worker 加速 |
| --- | --- | --- |
| 1 | 88.59 s | 1.00× |
| 2 | 53.05 s | 1.67× |
| 4 | 24.02 s | **3.69×** |
| 8 | 27.93 s | 3.17×（回落） |

观察：1→4 worker 近线性加速；8 worker 回落至 3.17×，说明瓶颈已从本地调度转移到 **TypeSafe API 的限流/排队**（4 并发已贴近当前组织限流拐点）。

## 4. 分析与调优建议

1. **缓存是第一收益**：任何重复/重叠文本（RAG 重查、相同文档重跑、重叠窗口）几乎零成本。性别缓存跨调用复用，同一人名全局只判定一次。
2. **并行度建议保持 4–8**：4 是延迟甜点；8 触发限流回落。吞吐优先的批处理任务可用 8（牺牲约 15% 延迟换 2 倍并发窗口），延迟优先用 4。
3. **长文本成本主要在检测阶段**：每 token 一个 Noul 问题。短句场景占比高的语料可考虑检测阶段粗筛（后续优化方向：仅对词典命中的词元发检测问题）。
4. **分型批 64 是质量/延迟权衡点**：批越大单请求摊薄越明显，但实测批内干扰会稀释 NONE 判定（碎片混入），不宜再放大。

## 5. 方法与局限

- 每组仅跑一次（真实 API 计费），未做多样本均值——延迟数据含网络抖动与 API 排队噪声，量级可信、个位数不可；
- E3 各并行度用独立 JevNER 实例（缓存不互通），且 LONG 文本与 E1 不同（120 句模板），两组数据不可直接互比；
- 实体数随并行度 6→10 波动属 API 采样方差（各窗口独立判定），非并行导致的结果不稳定。

## 6. 成本估算

- E1+E2+E3 合计约 200 次 system_one 请求；
- 按 jev-latest $0.042/Mtok 计，本轮全部实验（含此前语言扫描与 e2e 回归）累计约 **$0.3–0.5**。

## 7. 结论

三项优化全部验证有效：

- 三级缓存把重复文本的延迟从秒级压到毫秒级（**约 11 000×**）；
- 窗口级并行把多窗口负载延迟压缩 **3.7×**（4 worker），8 worker 受 API 限流回落到 3.2×；
- 建议默认配置保持 `max_workers=4~8`、分型批 64、窗口 24k 不变；后续优化方向为检测阶段词元粗筛与性别判定的跨语种批量合并。
