# JevNER 0.1.0

JevNER 0.1.0 is the initial public release of a zero-shot multilingual
named entity recognition SDK built on System One judgment models. One call
returns a calibrated entity forest — every span typed with competitive
probabilities, nesting preserved as real tree structure — with no local
model to train, fine-tune, or download.

## Highlights

### Zero-Shot Recognition on Judgment Models

`JevNER` turns a System One judgment model (default `baseten/mammoth-1`,
switchable to any gateway model such as `jev-latest`) into a full NER
pipeline: token detection (Noul), span typing (Choice), gender
recognition (Choice), and tree assembly. The model returns calibrated
probabilities rather than generated text, so `Entity.types` carries every
competitive type ranked by relevance — one entity can be GPE *and* LOC
at once.

### Nested Entity Forests

`ner(text)` returns `list[EntityNode]` directly. Offsets always satisfy
`text == source[start:end]`, and nesting is derived from offset
containment: crossing spans attach to the nearest common ancestor as
siblings. `str(node)` renders the whole subtree as a readable tree, so
downstream consumers get structure for free — no post-processing.

### Open Taxonomy from JSON

Entity types and packs are open data. Any user — including
non-programmer consumers — can extend or override the 31 built-in types
and 4 packs via a three-section JSON document:

```json
{
  "entity_types": {"BRAND": "A brand or trademark name."},
  "entity_packs": {"ECOM": ["PERSON", "ORG", "BRAND"]},
  "default_packs": ["CORE", "ECOM"]
}
```

### World Language Coverage

The same pipeline scored 24 languages end to end across Asia, Europe,
and the Americas — Chinese, Thai, Arabic, Hebrew, Hindi, Turkish,
Indonesian, Filipino, Vietnamese, Japanese, Korean, English, French,
German, Spanish, Portuguese, Italian, Russian, Dutch, Polish, and more —
including unspaced scripts and low-resource languages, with zero
training.

## Changed

- Initial public API: eight root-package exports (`JevNER`, `Entity`,
  `EntityNode`, `EntityPack`, `EntityTaxonomy`, `EntityType`, `Gender`,
  `Person`).
- `Entity` carries `types` as ranked `(EntityType, probability)` tuples
  plus `start`/`end` source offsets; `type` / `base_probability`
  properties preserve single-type ergonomics.
- `EntityPack` and `EntityType` ship as open dataclasses driven by
  `EntityTaxonomy.from_json`; the closed-enum design never shipped.

## Fixed

- Prevented oversized request bodies (>65,535 bytes) from reaching the
  gateway: windows are sized from a byte budget and typing criteria carry
  labels only, so descriptions appear once in the state type table.
- Kept typing requests within the 512-total-option backend cap: typing
  batches narrow dynamically by option budget (512 / options per
  question) under any custom taxonomy.
- Detection stability: gray-zone tokens (Noul in [0.15, 0.5)) get three
  independent recheck rounds, keep the maximum — eliminating the
  per-request sampling misses on Chinese medical and place tokens.
- Nesting is never absorbed at merge time; both sides of a nested pair
  survive, with relations derived by `entity_tree()`.
- Transient gateway 5xx responses retry up to three times with
  exponential backoff (`RetryPolicy(max_retries=3, timeout=None)`).

## Performance

Measured end to end on the live gateway (single sample, cost-bounded):

| Workload | Latency | Cached re-run |
| --- | --- | --- |
| Short sentence | ~12 s | ~6 ms |
| 10-sentence paragraph | ~146 s | ~6 ms |
| 30-sentence document, 4 windows parallel | ~157 s (5.49x speedup) | ~6 ms |

# JevNER 0.1.0（中文版）

JevNER 0.1.0 是基于 System One 判决模型的零样本多语言命名实体识别 SDK 的首个公开发布版本。
一次调用即返回校准过的实体森林——每个 span 都带有竞争性概率分布，嵌套关系以真实的树结构保留——
全程无需训练、微调或下载任何本地模型。

## 亮点

### 判决模型之上的零样本识别

`JevNER` 把 System One 判决模型（默认 `baseten/mammoth-1`，可随时切换为
`jev-latest` 等网关内任意模型）变成完整的 NER 管线：词元检测（Noul）、
区间分型（Choice）、性别识别（Choice）与树组装。模型返回的是校准概率而非
生成文本，因此 `Entity.types` 携带按相关性排序的全部竞争类型——一个实体
可以同时是政区 GPE 和地点 LOC。

### 嵌套实体森林

`ner(text)` 直接返回 `list[EntityNode]`。偏移量恒满足
`text == source[start:end]`，嵌套关系由偏移包含关系派生：交叉 span 挂到
最近的公共外层作为兄弟节点。`str(node)` 直接渲染整棵子树为可读树形，
下游零后处理即可获得结构。

### JSON 开放式类型体系

实体类型与实体包都是开放数据。任何用户——包括不写代码的 C 端消费者——
都可以通过三段式 JSON 文档扩展或覆盖内置的 31 个类型与 4 个实体包：

```json
{
  "entity_types": {"BRAND": "品牌或商标名称。"},
  "entity_packs": {"ECOM": ["PERSON", "ORG", "BRAND"]},
  "default_packs": ["CORE", "ECOM"]
}
```

### 全球语种覆盖

同一条管线端到端实测覆盖亚欧美三洲 24 种语言——中文、泰文、阿拉伯文、
希伯来文、印地文、土耳其文、印尼文、菲律宾文、越南文、日文、韩文、
英文、法文、德文、西班牙文、葡萄牙文、意大利文、俄文、荷兰文、波兰文
等，含无空格文字与小语种，全程零训练。

## 变更

- 初始公开 API：根包导出八个名字（`JevNER`、`Entity`、`EntityNode`、
  `EntityPack`、`EntityTaxonomy`、`EntityType`、`Gender`、`Person`）。
- `Entity` 的 `types` 为按概率降序的 `(EntityType, probability)` 元组序列，
  并携带原文偏移 `start`/`end`；`type` / `base_probability` 属性保持
  单类型访问习惯。
- `EntityPack` 与 `EntityType` 以开放 dataclass 形态发布，由
  `EntityTaxonomy.from_json` 驱动；封闭枚举设计从未上线。

## 修复

- 阻止超大请求体（>65,535 字节）触达网关：窗口按字节预算切分、分型
  criteria 只携带标签（描述仅在 state 类型表出现一次）。
- 分型请求守住 512 选项总数上限：分型批次按选项预算动态收窄
  （512 ÷ 每问选项数），对任意自定义 taxonomy 都不超限。
- 检测稳定性：灰色区词元（Noul 落于 [0.15, 0.5)）做三轮独立复检取
  最大值——消除中文医药与地名词元的逐请求采样漏检。
- 合并阶段从不吸收嵌套：嵌套对两侧都保留，关联完全由
  `entity_tree()` 派生。
- 瞬态网关 5xx 最多三次指数退避重试
  （`RetryPolicy(max_retries=3, timeout=None)`）。
